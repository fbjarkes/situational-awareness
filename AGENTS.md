# AGENTS.md

Guidance for coding agents working in this repository. `CLAUDE.md` is a symlink to this file.

## Knowledge bundle (`knowledge/`)

`knowledge/` is an [OKF v0.2](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/main/SPEC.md) bundle. It records what the project knows about each indicator, which ideas are still unproven, and why decisions were made. Follow the spec plus the project rules below. Bundle-specific conventions are also recorded in `knowledge/references/project-decisions.md`.

### Structure

- `knowledge/index.md` is the bundle root. Its frontmatter holds only `okf_version: "0.2"`. No other `index.md` has frontmatter.
- Each topic folder (`breadth/`, `sectors/`, `references/`) has an `index.md` with one line per concept: `- [Title](file.md) - one-line description`.
- `knowledge/log.md` groups changes under `## YYYY-MM-DD` headings, newest first.
- `index.md` and `log.md` are reserved names and can't be used for concepts.
- Every other `.md` file is a concept: YAML frontmatter with a non-empty `type`, then a Markdown body.

### Concept frontmatter

Keys already in use. Keep them consistent with existing files:

- `type`: free text. In use so far: `Metric` (indicator definitions), `Market Insight` (a hypothesis), `Research Result` (study output), `Reference` (project records).
- `title`, `description` (one sentence), `tags` (YAML list), `resource` (canonical URL; leave it out for abstract concepts).
- `status`: `draft` | `stable` | `deprecated`. A missing value means `stable`, so always set it explicitly. Everything is currently `draft`.
- `generated.by`: the actor. Agents use `<producer>/<id>`, e.g. `codex/market-report-poc`; scripts use `process:<id>`, e.g. `process:breadth-study`. Add `generated.at` (ISO 8601 with UTC offset) when content changes in a meaningful way; existing files don't set it yet.
- `verified`: a list of `{by, at}`, where a person is `human:<id>`. Add an entry only after a review has actually happened. Never add one for format checks or for your own work.
- `sources`: a list of `{id, resource, title}`. `resource` is a URL or a bundle path with a leading slash.

### Body conventions

- Use `#` headings for sections. Common ones: Definition, Interpretation, Methodology gaps, Evidence limitations.
- Attach sources to specific claims with Markdown footnotes. The footnote label must match a `sources[].id`: `...average.[^tradingview-symbol]` plus `[^tradingview-symbol]: TradingView symbol overview, consulted 2026-10-25.`
- Link to other concepts with paths from the bundle root, starting with `/`, e.g. `[MMOF](/breadth/mmof.md)`. In folder indexes, links are relative to the folder.

### `market_report` extension

`market_report` is a project-specific frontmatter mapping, not a standard OKF key. It describes candidate report settings and rules: `symbol`, `section`, `evidence_status`, `enabled`, `condition`, `interpretation`, `implementation_status`, and similar. **No code reads it yet.** Changing it doesn't change the report, and implementing a feature in code doesn't update it automatically, so keep the two in sync by hand.

### Evidence rules

- A market claim or hypothesis stays `market_report.evidence_status: exploratory` and `enabled: false` until its sources, sample period, method, results and limitations are all recorded and reviewed.
- Keep what the user proposed separate from what the data shows. For example, "the user proposed that below 20 is rare" is a hypothesis, not a finding.
- Study results are descriptive. Don't present them as trading rules or edges. Quote N, the comparison baseline and the main limitations alongside any number.
- Metric definitions must state what is confirmed and what is still unknown. For example, the MMOH/MMOF universe and average type are undocumented, so don't assume S&P 500 or a simple moving average.
- Research results generated by a script (`breadth-crossing-study.md`) record the input file hashes and the command that reproduces them. Regenerate them from the script rather than editing the numbers by hand.

### When changing the bundle

1. Edit or add the concept file, with `status` and `sources` set.
2. Update the folder's `index.md`. For a new folder, also update `knowledge/index.md`.
3. Add a line to `knowledge/log.md` under today's date heading, creating the heading at the top if it's missing.
4. Check conformance: every non-reserved `.md` has parseable frontmatter with a non-empty `type`.

## Interpreting readings with the knowledge bundle

Report interpretations come from the knowledge bundle at report time, retrieval-augmented style. For each reading, look up the relevant concepts, read them, and write the interpretation from what they say. Don't hard-code interpretation text: knowledge must not be copied into Python strings or templates. A change to `knowledge/` should change the next report's interpretation without any code change.

- `breadth_interpretation()` in `market-report.py` only describes direction. It is the fallback (`method: "direction-only"`) when no interpretation has been supplied, not the interpretation.
- `market_report.interpretation` strings in frontmatter are hints for wording, not finished output.

The code does the retrieval and record keeping; the agent does the interpreting:

```bash
uv run market-report.py --context      # report JSON/HTML + reports/market-context-DATE.md
# agent reads the context file, writes reports/market-interpretations-DATE.json
uv run market-report.py render --report reports/market-report-DATE.json \
    --interpretations reports/market-interpretations-DATE.json
```

`render` rebuilds the HTML/JSON from the saved report without fetching again, so the interpretation always matches the values it was written for. It rejects a file for a different date and any `sources` path that doesn't exist in the bundle. Retrieval lives in `knowledge.py` (`load_concepts`, `retrieve`). Each report section in `SECTIONS` gets `sections.<name>.knowledge`, the retrieved concepts, and `sections.<name>.interpretation` (`method`, `text`, `sources`).

### 1. Start from the facts

Run with `--context` and read `market-context-DATE.md`. It holds the readings (latest, previous close, last 10 closes, as-of label) and the notes and warnings. The report JSON has the same data. For each series take `latest.close`, `as_of`/`latest_status` (intraday or close), `daily_change`, `five_session_change`, and the report's `notes` and `warnings`. The previous close is in `previous`.

### 2. Retrieve

The context file already contains the full text of the concepts `knowledge.retrieve` found. These are tagged `metric` (`market_report.symbol` matches), `related` (same `section`, or mentions a symbol or metric path) and `linked` (one hop through `insight_source`, `sources` or body links). That's a starting point, not a limit. To look further, select by frontmatter rather than reading the whole bundle:

```bash
grep -rl "symbol: INDEX:MMOF" knowledge/      # the metric concept(s)
grep -rl "INDEX:MMOF\|/breadth/mmof.md" knowledge/   # insights, conditions and studies that mention it
grep -rl "section: breadth" knowledge/        # section-level concepts
```

Then read the hits and follow their links: `market_report.insight_source`, `sources[].resource` paths that start with `/`, and links in the body (e.g. "Related insights"). Read whole bodies, not only the frontmatter. The limitations and methodology gaps are part of what you must take into account.

### 3. Match the reading to the knowledge

Decide which recorded findings apply to this exact reading, and be precise about scope:

- **Level vs crossing.** The breadth study measures *downward crossings* (previous close ≥ threshold, current close < threshold), not every day spent below it.
  - MMOF going from 21.0 to 18.4 is a below-20 crossing.
  - MMOF at 18.4 after a week under 20 is not one. Say the crossing statistics don't directly cover that situation.
- **Intraday.** A crossing based on an intraday value is provisional until the close. Say so.
- **Combined conditions.** A condition that needs several series (e.g. `extreme-low-breadth.md` needs both MMOH and MMOF below 20 on the same date) matches only if every series meets it on the same observation date. Use the JSON's `as_of` labels to check.
- **No match.** If the knowledge doesn't cover the reading (e.g. MMOF at 85, where no high-breadth insight exists), say no recorded insight applies and describe only the level and direction. Don't fill the gap with general market knowledge presented as project knowledge.

### 4. Write the interpretation

- Stay within the section format: one or two sentences per section.
- Use only what the retrieved concepts support. Include the key number together with its sample size and baseline, and say how strong the evidence is. Everything is currently `exploratory`, so say "exploratory study", not "signal" or "edge".
- Respect `enabled: false`. A disabled insight must not be presented as a triggered signal. At most, mention that an unvalidated hypothesis exists.
- Keep the user's ideas separate from what the data shows (see Evidence rules above).
- List the concept files you relied on (bundle paths) in `sources` in the interpretations file. `render` stores them in the report JSON so every interpretation can be traced back to its sources. The HTML stays free of provenance details.
- Write it to the interpretations file and run `render`. Never edit the report HTML/JSON by hand.

Example. MMOF closes at 18.4, down from 21.0. Retrieval returns `/breadth/mmof.md`, `/references/breadth-crossing-study.md` and `/breadth/extreme-low-breadth.md`. A grounded interpretation:

> MMOF crossed below 20 today. In an exploratory 2002–2026 study, the 40 earlier crossings were followed by a mean 50-session SPY return of 5.19% (78% positive), against 1.80% for all days. Events cluster and the result isn't validated.

If MMOH is still above 20, the both-below hypothesis doesn't match. Don't mention it as triggered.

### 5. Feed gaps back into the bundle

If an interpretation needed knowledge that doesn't exist, or retrieved concepts contradict each other, don't patch it over in the report text. Point out the gap, and if the user agrees, add or fix the concept (following "When changing the bundle") so the next retrieval finds it.
